# 医院试用反馈版部署说明（2026-10-16）

本次发布含年龄更正、用药按钮修复、按访视上传费用照片、二院版 PHQ-9/GAD-7、逐页保存及待审核自行撤回。费用分类保持原样。两份量表向所有患者开放。快捷更正原因仍为必填；审核通过后由总管理员退回。

## 适用环境

现有生产容器 edc-prod-backend、edc-prod-mysql、edc-prod-nginx，MySQL 8.4，原项目内保留 hospital-edc-backend/.env.production。前置版本须已包含 20261012 CRF 和 20261014 患者图片/细分组迁移，Pillow 12 或以上。脚本会在维护前验证前置条件，失败时不要跳过检查。

脚本从独立发布目录构建镜像，通过运行容器标签找回原 Compose 项目、配置和持久化卷，不在新目录建立另一套生产数据库。不改服务器密码、中心、账号、Nginx/证书配置，也不执行演示初始化或试用清理。

## 执行

请先通知院方暂停录入，在医院服务器的同一个 Linux Bash 终端（具备 Docker 权限，通常 sudo -i 后）运行。不要在 Windows 本机执行。

从 GitHub 获取本次发布，建议使用聊天中给出的精确提交号。仓库为 https://github.com/fujiimoku/hospital-edc.git，发布分支 codex/release-20261008。进入新下载的发布目录，执行：

```bash
bash deploy/update-feedback-20261016.sh
```

脚本依次完成：

1. 恢复原 Compose 配置、保存旧镜像、构建新镜像，检查依赖、接口、持久化卷和前置表结构。
2. 暂停网站入口和后端，备份数据库、上传文件、环境及 Compose 配置。备份仅放在服务器私有目录，不进入 GitHub。
3. 为所有旧表旧字段保存行数与内容哈希，增加 patient_images.visit_id、外键和索引，验证旧数据完全不变。迁移可重入，允许补齐中断后缺失的索引/外键，不回填旧照片的访视。
4. 启动新后端，检查健康状态和数据库连接，再恢复 Nginx 并检查首页。

该脚本沿用此前未标记 Alembic 版本的增量迁移方式，不自动运行全历史迁移，也不自动更改 alembic_version。不要额外照旧说明执行 alembic upgrade head。

成功应显示“更新完成。网站入口检查通过。”并输出备份目录和镜像名称。保存这些输出。备份默认位于 $HOME/edc-backups/feedback-时间-提交号；后续 Compose 管理继续使用容器标签中的配置及原目录 deploy/active-release.override.yml。

## 失败与回退

构建或前置检查失败不会主动停止现有服务。维护开始后失败，脚本保持入口停止，避免迁移未校验就继续写入。保留报错及备份目录，排查后再恢复。不要反复盲目执行、清库、删卷或重建密钥。

仅需回退应用镜像时，在本次发布目录执行：

```bash
bash deploy/update-feedback-20261016.sh --rollback '脚本输出的完整备份目录'
```

回退不会恢复旧数据库覆盖新数据，也不会删除新增列。已有新照片绑定访视时会阻止自动回退，需评估后处理。脚本保留旧镜像和备份，但没有在医院服务器实际执行或完成生产恢复演练。

## 上线后验收
